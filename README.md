# 栖间 · A Quiet Corner

React + Vite 前端、**Node.js 24 + Express 5 后端**的个人记录空间。现支持单管理员登录和真实 Markdown 文章管理：新建、编辑、草稿、发布、撤回和永久删除。保留全部旧文档兼容，不会在初始化或测试时改写原有文章。

## 1. 首次运行

要求 Node.js **24 或更高版本**，无需数据库。现有依赖未增加新的生产包。

```sh
npm install
npm run admin:setup
```

按照终端提示设置用户名和密码。用户名为 3–64 个中英文字母、数字、下划线、点或短横线（不能以点/短横线开头），密码为 **12–128 个字符**；密码输入隐藏并要求确认。**没有默认管理员、默认口令或公开注册/网页初始化接口**。

账号仅保存随机 salt 和 scrypt 哈希。初次创建后启动后端；如后端已启动，设置或重置后需要重启。

在两个终端分别运行：

```sh
npm run server
npm run dev
```

- 后端默认端口 `3000`；未指定 `HOST` 时监听 `0.0.0.0`，仅需本机访问可设 `HOST=127.0.0.1`。
- 前端使用 Vite 显示的地址，通常为 `http://localhost:5173`；打开头像菜单选择“管理员登录”。
- 开发请求经 `/api` 同源代理；不要用 `file://` 打开页面，也不要将前端指向未配置 CORS 的另一个 API 来源。
- 可复制 [.env.example](.env.example) 为本地 `.env`：Node 启动命令与 Vite 都会加载它。环境变量文件不会提交。
- 如果改了后端 `PORT`，开发代理会跟随；也可用 `API_TARGET` 显式指定目标。代理必须保留浏览器的 `Host`（当前配置已做到）。

### 重置管理员

```sh
npm run admin:setup -- --reset
```

已有管理员不会被普通初始化覆盖。重置后**重启后端**，使新凭据生效并使全部旧会话失效。自动化可临时注入 `ADMIN_USERNAME` / `ADMIN_PASSWORD` 环境变量；人工操作推荐隐藏输入，不要把密码写进命令行参数、代码或环境变量文件。可用 `DATA_DIR` 指定私有数据目录，初始化命令与后端必须使用相同目录。

## 2. 页面与文章操作

- `/login`：管理员登录；没有配置账号时，提示运行本地初始化命令，不会允许访客创建站长账号。
- `/manage`：管理列表，可筛选全部、草稿、已发布文章。
- `/write`：新建文章；可填写标题、日期、分类、标签、自定义摘要、置顶和 Markdown 正文。
- `/manage/posts/:slug/edit`：编辑现有文章，提供 Markdown 预览、保存、发布/撤回及永久删除。
- 登录后的公开文章页提供编辑入口；首页“写点什么”会进入写作流程。

**保存为草稿不会公开**。已发布文章的普通保存保持发布状态，只有明确撤回才转为草稿。新文章链接可留空自动生成；创建后链接不可重命名。正文从编辑器提交时不含元数据块，由后端安全生成 front matter；正文开头的 `---` 仍保留为正文。

这是手动保存，不是自动保存。未保存时刷新/关闭页面或点击编辑器的返回按钮会提醒；尚未拦截所有站内导航与浏览器后退，请先保存。保存失败不显示成功。编辑和删除都要求当前 `version`：如另一标签页或本地 Markdown 文件已修改，返回 `409`，不会覆盖旧版本。先复制/备份当前未保存正文，再重新加载并合并；会话失效时可在新标签页重新登录后回到编辑器继续处理。**删除是永久删除，没有回收站和版本历史，请先备份。**

公开阅读仍支持分类、标题/摘要/标签搜索、日期筛选、日历、排序、中文链接、四种时段氛围与浏览器本地外观偏好。日历不会根据文件修改时间或正文学习进度捏造发布日期。

## 3. 存储与兼容

- [server/document](server/document) 中无 `status` 的旧 Markdown 视为已发布；阅读不需要迁移，也不会因启动服务而被重写。
- 私有数据默认位于 `server/data`：账号哈希 `admin.json`，草稿在其 `drafts` 子目录。整个目录已被 Git 忽略。
- 新建草稿写入私有目录；发布/撤回时转移至对应目录，编辑使用临时文件原子替换，转移使用排他硬链接后移除源文件，不会覆盖期间外部创建的同名文章。即使手工把 `status: draft` 的文件放进公开文档目录，公开 API 仍不会返回它。
- 发布/撤回要求 `DATA_DIR` 与 `DOCS_DIR` 位于同一个支持硬链接的文件系统（例如 NTFS/ext4）。采用单 Node 进程写入队列，**不支持多实例共享写目录**。极端中断可能遗留同名副本，管理接口会报 409，请先备份并在服务器解决冲突；撤回状态优先隐藏，不会把草稿当公开文章。
- 保存会保留未涉及的旧 front matter 字段；首次在界面编辑旧文档时，受管理字段按表单归一化。请求前已完成的手工修改会使旧版本失效；文件系统没有跨进程锁，手工编辑/同步文件请停服或确保没有网页同时保存，不要并发使用外部写入程序。
- 服务端只解释 YAML / JSON 元数据，禁用可执行 JavaScript front matter。损坏文件会被列表跳过并在服务器告警，其他文章仍可访问；其详情会提示需要修复原文件。
- 文章列表不返回整篇正文；管理列表也不会携带全文。草稿只允许经过认证的管理接口读取，公共详情接口即使已登录也只返回已发布文章。

**备份必须同时覆盖公开文章目录、私有草稿目录和管理员哈希文件。** 不要静态托管整个仓库、`server` 或私有数据目录。Windows 上权限取决于 NTFS ACL，部署账号应限制其他用户读取私有数据；Unix 下新账号文件/目录分别请求 `0600`/`0700`。

### 可选文章元数据

```yaml
---
title: 给生活留一点空白
date: '2026-10-28'
type: note
tags:
  - 随想
  - 生活
pinned: true
excerpt: 可选自定义摘要。
status: published
---
正文……
```

- `type` 为 `note` / `log` / `plan` / `uncategorized`；旧 `diary` 仍映射为日志。未标注时不猜测。
- 旧标签支持字符串数组或逗号分隔文本；管理接口要求数组，最多 20 个，每个 1–40 字符。
- 新建/编辑标题 1–200 字符、正文最多 512 KiB、自定义摘要最多 500 字符（展示摘要最多 140 字符）；发布时正文不能为空。
- 写接口日期仅接受真实 `YYYY-MM-DD` 或空串；空日期明确表示不标注，不会改用文件日期。旧标题/文件名日期仍兼容，带时区的 YAML 日期保留其书写的日历日期。
- 摘要为空时动态从真实正文提取。`pinned` 不是权限，`type: plan` 不是提醒或计划管理。

## 4. 接口与安全

统一前缀 `/api`，错误格式为 `{ "error": "可读说明" }`。认证和文章响应使用 `Cache-Control: no-store`，避免退出/撤回后复用旧缓存。

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/health` | 健康检查 |
| GET | `/auth/session` | `{user, csrfToken, configured}`，未登录的前两项为 `null` |
| POST | `/auth/login` | JSON `{username,password}`，成功设置会话 Cookie 并返回 session 形状 |
| POST | `/auth/logout` | 需登录与 CSRF，销毁会话，204 |
| GET | `/posts` | 只返回公开文章摘要数组，兼容旧接口 |
| GET | `/posts/:slug` | 公开文章详情，草稿/不存在为 404 |
| GET | `/admin/posts?status=all` | 需登录；状态可为 `all` / `draft` / `published` |
| GET | `/admin/posts/:slug` | 需登录；详情含正文、`customExcerpt`、`version` |
| POST | `/admin/posts` | 需登录与 CSRF；创建，成功 201 |
| PUT | `/admin/posts/:slug` | 需登录与 CSRF；完整更新，必须提交当前 `version` |
| DELETE | `/admin/posts/:slug` | 需登录与 CSRF；JSON `{version}`，成功 204 |

创建/更新 JSON 字段为 `title, content, date, type, tags, excerpt, pinned, status`，创建时可加可选 `slug`，更新时再加 `version`。`excerpt` 是自定义摘要：编辑器应从详情的 `customExcerpt` 回填，不要把自动生成的展示摘要写回。已有文章链接不可修改。

登录及文章写入须为 `application/json`。成功登录后，把 session 返回的 `csrfToken` 以 `X-CSRF-Token` 请求头发送到注销、创建、更新和删除接口，并带同源 Cookie。未登录 401、CSRF/来源失败 403、版本冲突/链接重复 409、缺失版本 428；数据错误 400、非 JSON 415、请求体超限 413。

安全边界：

- 密码采用 Node.js 内置 `crypto.scrypt`，随机 salt、固定成本、常量时间比较；不保存明文。
- 会话为随机 256 位令牌，后端只保存 SHA-256 摘要；Cookie 为 `HttpOnly; SameSite=Lax; Path=/api`，生产模式额外 `Secure`。固定有效期 12 小时，成功登录轮换会话，退出立即销毁；服务重启后全部会话失效。
- 登录每直连地址 15 分钟最多 10 次、最多 4 个并发密码计算。计数不信任 `X-Forwarded-For`；反向代理后的请求会共享代理地址限额，公网可再配反代限流。
- 浏览器变更请求检查 `Origin` 和 Fetch Metadata，另用会话 CSRF 令牌保护，不配置宽泛 CORS；管理接口所有操作（包括读取草稿）均鉴权。
- 文件名限制、目录边界和普通文件检查防止路径穿越、Windows 设备文件/ADS 和符号链接；响应不暴露内部异常/密码哈希。
- 发布过的内容可能已被他人保存/搜索引擎抓取，撤回只能停止本站继续提供，无法收回既有副本。

## 5. 构建与部署

```sh
npm run lint
npm test
npm run build
```

测试使用临时账号、文章和服务器，不会登录真实站长或修改现有文档。覆盖密码哈希/初始化、会话轮换与失效、CSRF/Origin/限速、全部 CRUD/发布撤回、版本冲突、路径与元数据校验、私有数据不被静态托管、旧文档及日期/搜索/氛围逻辑。测试使用 Node 的进程内隔离模式，构建使用原生配置加载，以兼容 Windows 受限子进程环境。

本地验证完整构建（仅开发/本机使用，普通 HTTP Cookie）：

```sh
npm run server -- --serve
```

访问 `http://localhost:3000`，后端同时托管构建产物、`/api` 和 SPA 路由回退，不需要另开 Vite。`vite preview` 仅预览静态产物，不代理后端，不适合验证登录/写入。

生产环境使用 HTTPS 反向代理，例如 PowerShell：

```powershell
$env:APP_ORIGIN = 'https://blog.example.com'
$env:HOST = '127.0.0.1'
$env:TRUST_PROXY = 'loopback'
npm start
```

- `npm start` 启用生产模式、Secure Cookie、静态托管与 SPA 回退。必须设置 HTTPS `APP_ORIGIN`（来源不能带路径/末尾斜杠；多个可信来源以逗号分隔），构建产物必须先存在。
- HTTPS 由反向代理终止并转发到 Node；代理应保留 `Host`，正确转发 `X-Forwarded-Proto`。只在确实信任该代理的网络中设置 `TRUST_PROXY`，不要任意相信公网传来的转发头。
- 容器/云平台需要监听公网接口时设 `HOST=0.0.0.0`；`PORT` 使用平台指定端口。`DATA_DIR`、`DOCS_DIR` 应挂载持久卷并位于同一文件系统，不能依赖容器临时层。
- 可用 `STATIC_DIR` 指向其他构建目录；只将该静态构建目录暴露给浏览器。
